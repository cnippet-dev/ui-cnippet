cnippet ui uses a CSS variables-based theming system built on Tailwind CSS v4. Every color and the radius are design tokens you can override — globally or scoped to a single component.

## How It Works

Components reference semantic CSS variables (`--primary`, `--muted`, `--border`, etc.) rather than hard-coded values. Changing a variable updates every component that references it.

```css title="app/globals.css"
:root {
  --primary: var(--color-neutral-800);
  --primary-foreground: var(--color-neutral-50);
}
```

Tokens point at the [Tailwind CSS palette](https://tailwindcss.com/docs/colors), mixes of it (`color-mix()`) or translucent black and white (`--alpha()`). An `@theme inline` block turns each token into Tailwind utilities, so `--primary` gives you `bg-primary`, `text-primary` and opacity modifiers like `bg-primary/10`:

```css title="app/globals.css"
@theme inline {
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
}
```

## Default Colors

The default palette is neutral-based. Install it with the CLI:

```bash
npx shadcn@latest add @cnippet/colors-neutral
```

[Colors](/docs/colors) shows every token with its light and dark value, and has the full CSS to copy. [Manual Installation](/docs/installation/manual) has the complete stylesheet, including the `@theme inline` mappings.

## Extended Tokens

cnippet ui adds semantic tokens for feedback states not covered by the base shadcn/ui scale:

```css
:root {
  --info: var(--color-blue-500);
  --info-foreground: var(--color-blue-700);

  --success: var(--color-emerald-500);
  --success-foreground: var(--color-emerald-700);

  --warning: var(--color-amber-500);
  --warning-foreground: var(--color-amber-700);
}
```

These are consumed by `<Alert>`, `<Badge>`, and `<Toast>` when using `variant="info"`, `"success"`, or `"warning"`.

## Dark Mode

Every token has a second value in a `.dark` block. Adding the `dark` class to `<html>` switches every component to those values.

```css
.dark {
  --primary: var(--color-neutral-100);
  --primary-foreground: var(--color-neutral-800);
}
```

[Dark Mode](/docs/dark-mode) covers setup for Next.js, Vite, React Router, TanStack Start and Astro, a theme toggle, and how to avoid a flash of the wrong theme.

## Custom Themes

Override any subset of variables to create a custom palette. Set both the light and the dark value. Here's a blue-focused theme:

```css
:root {
  --primary: var(--color-blue-600);
  --primary-foreground: var(--color-white);
  --ring: var(--color-blue-400);
}

.dark {
  --primary: var(--color-blue-500);
  --primary-foreground: var(--color-white);
  --ring: var(--color-blue-500);
}
```

Everything you don't override falls back to the defaults. You can also use any CSS color, such as `oklch(0.55 0.2 260)` or `#2563eb`.

## Border Radius

The `--radius` variable drives the global radius scale. The `rounded-sm`, `rounded-md`, `rounded-lg` and `rounded-xl` utilities are calculated from it, so the whole UI scales together:

```css
:root {
  --radius: 0.625rem; /* default — try 0.25rem for sharp, 0.875rem for rounder */
}

@theme inline {
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) + 4px);
}
```

## Per-Component Overrides

For variants, data attributes and wrapper components, see [Customization](/docs/handbook/customization).

Because components are copied into your project, you can scope token overrides with inline styles:

```tsx
<Card style={{ "--radius": "1rem" } as React.CSSProperties}>
  ...
</Card>
```

Or set tokens on a class and apply it to a section:

```css
.brand {
  --primary: var(--color-violet-600);
  --primary-foreground: var(--color-white);
}
```
